Program Development Tips

The following steps outline a general approach to designing and developing a program for this course. They assume you are using Java with an IDE or a UNIX, Linux, or Mac command line, but most steps apply to any language.

Before You Begin

  • Use version control, such as Git, and back up your work regularly. A lost or corrupted file should not cost you your progress.
  • If you get stuck or are unsure how to proceed, ask for help early, through office hours, a teaching assistant, or the course discussion forum. Do not wait until the deadline.

Development Process

  1. Read the problem statement and specification carefully, and start early rather than waiting until the due date. If you need to make an assumption to move forward, confirm it with the instructor when possible, and document your assumption either way.
  2. Identify the required inputs and outputs. Review any sample data or examples provided so you understand how the program should transform the data. Avoid writing a skeleton input and output program before you have designed a solution, since it can tempt you to start coding before you have actually solved the problem.
  3. Design your solution before you write any code. Create pseudocode or a flowchart, break the solution into objects and functions, and decide on your data structures. Include this design overview in your documentation.
  4. Hand-trace your design using sample data to check its logic and catch errors before you begin coding.
  5. Implement your program using clear, consistent comments and formatting, and include any required documentation. Test it against the provided data sets, or create your own if none are given, and be sure to test edge cases such as minimum and maximum sizes. Compare your output to the expected results, and repeat the design, trace, and test cycle until the program works correctly.
  6. Complete any required analysis or written questions using your test results. You may need to run the program several times with different data sets, and some runs may take a while, so plan your time accordingly.
  7. Confirm that your program compiles and runs using the same software the grader will use, which is Eclipse for this course. Standard Java should behave the same across environments, but check anyway since this is not guaranteed.
  8. Submit your program and all required files as instructed. Verify the submission yourself by checking what you actually submitted, rather than asking the instructor to confirm it for you.
